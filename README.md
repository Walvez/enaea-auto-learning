# 中国教育干部网络学院（新版 estudy）自动连续学习脚本

一个 **ScriptCat（`.user.js`）用户脚本**：在 https://estudy.enaea.edu.cn 新版平台上，以 **1.0x 正常倍速**自动、连续地完成当前项目内**所有未完成的视频课程**，自动接续「下一集 / 下一课程 / 下一小节 / 下一大章」，直到全部指定视频课程完成即停止。
不加速、不拖动进度（不 seek）、不伪造学时、不调用任何写接口、不上传/保存 Cookie 或 Token。

> **一键安装（推荐）**：已装 ScriptCat 时，直接打开
> https://raw.githubusercontent.com/Walvez/enaea-auto-learning/main/enaea-auto-learning.user.js
> 即可弹出安装界面。仓库主页：https://github.com/Walvez/enaea-auto-learning

> 核心原则：**平台"官方显示"的进度才算完成**（目录/分集进度条 `aria-valuenow` 与 "N%" 文案）。脚本不会把 `currentTime≈duration` 当成平台完成。

## 2. 安装

1. 安装 **ScriptCat** 浏览器扩展（Chrome/Edge）。
2. 打开 ScriptCat → 新建脚本 / 导入脚本，把 `enaea-auto-learning.user.js` 的全部内容粘贴进来并保存。
   - 或直接把 `.user.js` 文件拖入 ScriptCat 导入。
3. 打开 https://estudy.enaea.edu.cn 并登录，进入「必修课 / 选修课」目录页。
4. 页面**右下角**出现悬浮面板即安装成功（也可在 ScriptCat 菜单里看到脚本命令）。

脚本通过 `@match https://estudy.enaea.edu.cn/web/*` 生效，纯页面内运行，**不依赖任何本地服务**。

## 3. 使用

- 点击面板上的 **【开始自动学习】** 才开始，脚本按下面顺序自动进行：
  1. **SCANNING** 扫描目录（自动展开所有折叠的大章/小节）；
  2. **SELECTING** 选第一个进度 <100% 的课程；
  3. 进入课程 → **依次播放本课程未完成分集**；
  4. 每集**真正播放结束**后 → **NEXT_EPISODE** 切下一集；
  5. 本课程最后一集结束并确认完成后 → 返回目录 → **NEXT_COURSE** 选下一门未完成课程；
  6. 课程可能跨**小节（NEXT_SECTION）**、跨**大章（NEXT_CHAPTER）**，脚本都会自动展开并进入；
  7. 全部指定视频课程完成后进入 **COMPLETED**，停止且**不会重播**。
- 按钮：**开始自动学习 / 暂停 / 继续 / 停止 / 重新扫描目录**。
  - **停止**后不会自动重启；**暂停**会真正暂停 `<video>`；**继续**从暂停处继续。
- 面板显示字段：
  - 当前大章、当前小节、当前课程、当前分集；
  - 当前视频进度（时间 + 进度条）；
  - 平台显示的课程进度；
  - 已完成课程数量（x / 总数）；
  - 播放速度（恒为 1.0x）；
  - 最近一次错误。
- ScriptCat 菜单里也注册了同名命令，可在无面板时调用。

## 4. 完成判定依据（关键设计）

- **以平台显示为准**：
  - 目录页每门课的进度条 `[role="progressbar"][aria-valuenow]`（0–100）+ 文本 "N%"；
  - 播放页每个分集的 `[role="progressbar"][aria-valuenow]` + "N%"。
- **不**用 `currentTime ≈ duration` 判断课程完成——它只用来判断"这一集播放到结尾"，最终是否算完成仍看平台进度是否到位。
- 每集结束用 `HTMLMediaElement` 的 `ended` 事件 + 播放到尾部 + 非暂停状态判定；结束后等待平台进度回写（`syncWaitMs`）再读取；若仍未达阈值则**有限重试**（超出 `courseAttemptCap` / `errorCap` 则标记人工或报错停止）。
- 外层的"重新扫描目录"循环会自愈个别进度延迟同步的情况。

## 5. 状态机

```
IDLE
  └─(开始)→ RUNNING
        SCANNING → SELECTING → PLAYING → WAITING_CONFIRMATION
              → NEXT_EPISODE / NEXT_COURSE / NEXT_SECTION / NEXT_CHAPTER → (回到 SELECTING/PLAYING)
RUNNING ↔ PAUSED        （暂停/继续）
RUNNING → STOPPED       （手动停止，不自动重启）
RUNNING → COMPLETED     （全部视频课程完成，不重播）
RUNNING → ERROR         （连续错误超限）
```

## 6. 目录 / 播放页适配（新版 estudy）

新版是 **React SPA + `grt` 组件库 + CSS Modules**，类名形如 `section-box_n5L9Q-kf`（`本地名_构建hash`）。脚本统一用 **[class*="本地名_"]** 前缀匹配，避免构建 hash 变化导致失效：

| 结构 | 选择器（前缀匹配） |
|---|---|
| 折叠项（大章=顶层，小节=嵌套） | `.grt-collapse-item` / `.grt-collapse-header` / `.grt-collapse-content` |
| 课程卡片 | `[class*="section-box_"]` |
| 课程标题 | `[class*="list-title_"]` |
| 进度条 / 百分比文本 | `[role="progressbar"]` / `[class*="progress-label_"]` |
| 播放页分集项 / 分集名 / 分集百分比 | `[class*="item-wrap_"]` / `[class*="name-span_"]` / `[class*="rate-span_"]` |
| 播放列表容器 | `[class*="play-list"]` |
| 返回目录（面包屑"课程学习"） | `[class*="return-icon_"]` |

- **"大章 / 小节"层级**用祖先 `.grt-collapse-item` 的数量（depth）判定，天然适配跨章跨节。
- **SPA 路由检测**：包装 `history.pushState/replaceState` + 监听 `popstate/hashchange` + 定时轮询，识别"目录页 → 播放页 → 目录页"以及切换分集时 URL 里 `resource_id` 的变化。

> 以上选择器来自**真实站点的实际 DOM 勘察**（不是对旧版 study.enaea.edu.cn 的猜测）。

## 7. 持久化与多标签

- 存储：`GM_getValue / GM_setValue`（无 GM 环境回退 `localStorage`），键：`enaea_state`、`enaea_lock`。
- 刷新/重开页面：
  - 状态为 **RUNNING** → **自动续跑**（无需重新点开始）；
  - 状态为 **PAUSED** → 转为 **IDLE**，等待用户手动继续（不会莫名自动跑）。
- **不会**在刷新后无限重开同一门课：完成/尝试次数按课程 key 记账。
- **多标签**：一把锁；抢不到锁的标签只读展示、不重复启动；持锁标签定期心跳续约，关闭后释放。

---

## 8. 异常处理

- 慢加载 / 播放器初始化失败 / 自动播放被拦截：有限等待重试；被拦截时进入"等待用户手势"（点击一次页面任意处即可恢复播放，绝不修改倍速）。
- 网络中断 / 列表延迟渲染 / 状态陈旧：等待 + 重新扫描 + 有限重试。
- 连续错误超过 `errorCap` → 进入 ERROR 并在面板显示"最近一次错误"。
- **验证码 / 确认弹窗 / 考试 / 问卷**：检测到即**暂停并提示人工处理**，不做任何绕过或模拟。

---

## 9. 非视频项

VR 参观、测验、问卷、无分集课程等：**标记为"需人工处理"**，不模拟播放、不伪造进度，脚本会跳过并继续下一项。

## 12. 常见问题：自动播放被拦截 / 提示“已静音” / 面板短暂显示“无 video 元素”

新版播放器是 **xgplayer + 浏览器自动播放策略**，这是实机调试的**主要坑**，1.0.1 已针对性处理：

- **“无 video 元素”**：播放页切集时 `<video>` 会被销毁重建，旧版在重建瞬间检测失败就报错退出。1.0.1 改为 **轮询等待 video 就绪**（含同源 iframe 内查找），不再瞬时抛错。
- **自动播放被拦截**：无用户手势时 `video.play()` 会抛 `NotAllowedError`。1.0.1 兜底为**静音自动播放**（`muted=true` 后 `play()` 一定成功，学时正常累计、倍速仍 1.0x），保证连续学习不中断；此时面板会出现一行提示“已静音自动播放…点击页面任意处可恢复声音”。
- **想要有声音**：在页面上（含本面板）**任意点击一次**即可恢复声音；如果你是在本面板点“开始自动学习”启动的（真实点击手势），通常可直接**带声音**正常播放，不会触发静音兜底。
- 若极少数环境连静音播放也被拦截，面板会显示“请在页面上点击一次以继续”，点一下就继续。

> 说明：静音仅为**绕过浏览器自动播放策略**，不改变 1.0x 倍速、不 seek、不伪造时长；平台按真实播放计时，学时照常累计。

## 13. 常见问题：会“乱跳课程 / 漏掉前面的课”（1.0.2 已修）

- **现象**：明明前面（如“理论教育 → 政治理论学习”）还有没刷完的课，脚本却直接跳到后面某一门（例如“知识技能教育”里的课）。
- **根因**：目录是折叠列表，**小节内容要展开后才会被渲染进 DOM**。旧版“一键展开”一次性拿到整批节点后连续点击，但页面框架（React）每次展开都会**重渲染并替换这些节点**，导致只有 1 个小节被真正展开，其余小节始终没有课程内容 → 扫描时**漏课**（只读到 64 门中的一部分），于是按残缺列表选了后面的课。
- **修复**：改为**每次点击前重新查询 DOM、只点击“当前没有课程内容”的小节**，绝不点击已展开项（避免被收起），逐个小节展开并等待其渲染完成。修复后实测可稳定读到**全部 79 门**（理论教育 17 / 党性教育 42 / 知识技能教育 20），并按目录顺序选到**第一门未完成课**。
- **顺带修复**：升级到 1.0.2 时会**自动清理旧版被污染的进度状态**（偏小的总课数、被误标“人工”的课程、指向错误课程的当前项），确保重新按正确顺序开始；从播放页点“开始”也会**先回目录做权威重扫**再选课。

## 14. 常见问题：播放页“这一集还没看完就跳到下一集了”（1.0.3 已修）

- **现象**：某门课有多集，比如第一集才看到 10%、第二集 5%，脚本却直接跳到第二集在放，第一集被“跳过”了。
- **根因（实机定位）**：点分集后，播放器目录的**高亮先变**，但 `<video>` 的 `src` 要晚一点才真正换成新的一集；旧版只等“是否高亮”就开始播放，于是实际还在放**上一集/默认的那一集**，却把“目标那一集”记成本地完成 → 表现为跳集、且被跳的那集进度不动。
- **修复（1.0.3）**：
  1. **切集必须“视频真的切过去”**：用每集时长（如 29:58 / 29:06 / 30:05）做校验，`<video>.duration` 与目标集时长相符才认为切换成功，杜绝“高亮切了视频没切”。
  2. **永远从第一集（最小未完成集）开始**，即使平台上次停在后面某一集，也会先切回最靠前的未完成集。
  3. **到 100% 再进下一集**：每集播完后再回读该集的平台展示进度，确认到 100% 才进入下一集；视频确实整集播完但平台同步稍慢时，短暂轮询后信任并继续（稍后目录页会复核），**不会**把没确认完成的集跳过。
  4. 修掉一个隐性 bug：右侧“授课讲师/简介”信息块和分集用了同一个 `item-wrap_` 类名，旧版会把**讲师简介**误当成“多出来的一集”反复去点。1.0.3 只在播放器**目录容器(play-list)**内读取分集，并过滤掉没有分集名/进度指示的信息块。
- **关于“从头看”**：脚本**不 seek、不改倍速**。未到 100% 的分集，平台会自动从上次位置续播，把它一路播到本集结束即累计到 100%；不会为了“从头”去拖进度条（拖进度条属于伪造，平台也不认可学时）。

## 15. 常见问题：又“从第二门课开始”、跳过了才 10% 的第一门（1.0.4 已修）

- **现象**：明明「理论教育 → 政治理论学习」里第一门《习近平党建文选》才 10%，脚本却从第二门《深入学习领会…》开始，第一门像被无视。
- **根因**：这是**旧版本残留的“人工”标记**在作怪。之前几版遇到过“无 video 元素 / 自动播放拦截 / 跳集”等错误，重试到上限后会把该课写进持久化的“人工处理”名单（面板上显示 `(人工)`）。这些名单存在浏览器 GM 存储里、**跨会话保留**。即使后续版本已经修好播放问题，选课逻辑仍会**无脑跳过所有“人工”名单里的课**——于是 10% 的第一门被跳过了。
- **修复（1.0.4）**：
  1. **有进度的课永不被“人工”标记跳过**：`0 < 平台进度 < 100` 说明它是能播的视频课，选课时**一定重新尝试**，不再因历史“人工”标记被跳过；只有“0% 且被确认非视频（VR/测验/问卷/多次失败）”的才跳过。
  2. **升级自动清污**：状态版本升到 3，检测到旧版保存的状态会**自动清空**被污染的 `人工/尝试次数/current` 等，保证从干净状态按目录顺序选第一门未完成课。
  3. **尝试次数按会话重置**：不再把上一轮的“进入次数”带到这一轮，避免一进来就“次数已满 → 直接判人工”。
  4. 顺带把“本次运行已放弃”与“历史人工”分开记录，避免同一会话里对同一门课反复重试死循环。
- **实测（真实站点）**：伪造“第一门(10%)被标人工”的旧状态后 → 加载即被清空；即使强制把第一门和一门 0% 课**都**标人工，选课仍返回 **第一门(10%)**；点“开始”实机进入的正是 **《习近平党建文选》第一卷、第二卷学习辅导（第一集，播放器时长 1798s）**，不再跳到第二门。

## 16. 常见问题：右下角出现“两个面板” / 点“开始”没反应（1.0.5 已修）

- **现象**：页面上同时出现两块 ENAEA 面板（一块“运行中/正常播放”、一块“已停止/各项为 -”），点其中一块的“开始自动学习”另一块不动、或整体像“点了没反应”；面板可能停在“运行中 / 扫描目录”、已完成 `0 / ?`。
- **根因**：同一页面被**注入了两份脚本实例**（双引擎）。常见于：① 用 ScriptCat 安装后又手动注入了同一脚本；② ScriptCat 里同时装了两份（不同来源）自动学习脚本；③ 测试/调试时残留的旧标签页里已注入过一份，又叠加了 ScriptCat 的注入。两份实例各自维护状态与面板，互相抢多标签锁、互相打断，表现为“没反应 / 两个面板”。
- **修复（1.0.5）**：加入**单实例守卫**——每个页面只允许一个实例运行。启动时检测是否已存在面板节点（`#__enaea_panel_host__`）或“已激活”标记，若已有实例则**本实例安静退出**，不再创建第二个面板、不再启动第二个引擎。该判断基于共享 DOM，因此**跨脚本世界也能生效**（ScriptCat 与手动注入、或 ScriptCat 装了两份都能被识别）。
- **你还需要做的**：把浏览器里残留的**旧标签页/旧标签**（尤其是调试用过的页面）关掉并刷新一次当前学习页；并确认 ScriptCat 里**只保留一份**本脚本（多余的旧版本删除）。之后面板只会有 1 个。

## 17. 常见问题：某集平台真实进度才 10% 多，却从 90% 多开始播、跳下一集后又“从头重看”（1.0.5 已修）

- **现象**：面板/目录里第一集平台展示进度才 13%，但视频实际是从 29:32/29:58（约 93%）的位置续播；播几下就“到结尾”，平台进度几乎不涨；然后切到下一集，又像是从头开始。
- **根因**：播放器把每一集“上次播到哪”记在浏览器本地（localStorage `_h5player_media_progress`，按 resource_id 记录 `{progress,duration}`）。这个**本地续播位置**可能远高于**平台真实进度**（平台进度是服务端按有效学习时长累计的，二者不同步）。旧逻辑直接从这个很靠后的本地位置播，几十秒就播完，但平台几乎不涨进度，于是判定“没到 100% → 重播本集”，看起来就是“从 90% 多开始、又跳回开头重看”。
- **修复（1.0.5）**：新增 `alignToPlatformProgress()`。进入某一集、开播前，读取该集**平台展示的真实进度 P%**：若 `<video>` 当前续播位置**明显超过** P%（超过约 3% 且 >4 秒），就把播放起点**回退到平台真实进度 P% 的位置**，再以 **1.0x 实时、不 seek 快进、不伪造** 的方式把剩下的部分真实看完，直到平台确认到 100% 再进下一集。
  - 只“往回对齐到真实进度”，**绝不会**把播放位置向前快进到超过平台进度（不刷学时、不作弊）。
  - 这样既尊重“平台真实进度”，又避免“从 90% 多秒播完、平台不涨、又从头重看”的来回折腾。
- **实测**：真实站点 `_h5player_media_progress` 确认同 resource_id 存在 `progress=1797.7/duration=1798.3`（≈100%）、`341.8/1746` 等本地记忆位置，与平台展示进度不一致；夹具用例 **S7** 验证：平台进度 10%、人为把视频放到 90% 后调用对齐 → 播放位置被回退到 **10%**（`before=0.90 → after=0.10`）✔。
